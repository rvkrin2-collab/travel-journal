# Как создать новое путешествие

## Самый простой способ: с телефона

1. Откройте на сайте `/author.html` — страницу можно установить на главный экран как приложение.
2. Заполните название, период и описание поездки.
3. Добавьте любое количество глав. Для каждой главы укажите темы и места обычными словами через запятую.
4. Для каждой главы нажмите **«Выбрать из Google Фото»**. Выбранные файлы сразу копируются в постоянное R2-хранилище сайта.
5. Нажмите **«Отправить и запустить обработку»**. Сайт сам передаст заявку и запустит анализ.
6. Откройте выданную страницу статуса. Когда глава готова, на ней появится ссылка на редактор со всем исходным набором фотографий.

Черновик автоматически хранится на телефоне, поэтому форму можно закрывать и продолжать позже. Программировать, отправлять JSON, открывать Codex или заходить в GitHub не требуется. Кнопка скачивания JSON оставлена только как резервная копия.

Если описание всех глав уже подготовлено, раскройте **«Вставить все главы одним текстом»**, вставьте блоки вида `Глава 1 — Название`, описание, `Темы: …`, `Места: …` и нажмите **«Заполнить главы из текста»**. Если главы с такими названиями уже существовали, загруженные для них фотографии сохранятся.

После первого утверждения фотографий ничего скачивать и передавать не нужно: редактор отправляет author-review сам, запускает storyboard и возвращает ссылку на страницу статуса. Страница статуса показывает один общий маршрут работы и отдельное состояние каждой главы. Когда появится кнопка **«Открыть и утвердить preview»**, проверьте собранную главу и нажмите **«Утверждаю preview»**.

Когда утверждены preview всех глав, на той же странице появится финальный блок **«Публикация»**. Выберите главу, чьё главное фото станет обложкой путешествия, поставьте галочку прямого подтверждения и нажмите **«Опубликовать путешествие»**. Только эта отдельная команда запускает сборку публичных страниц и добавляет путешествие на сайт; утверждение отдельной главы само по себе ничего не публикует.

Google-вход нужен только для выбора фотографий и первоначальной отправки путешествия. После отправки Worker создаёт отдельный подписанный авторский сеанс на 12 часов; утверждение фотографий, preview и финальная публикация выполняются без повторного входа в Google. Если полностью закрыть браузер или дождаться окончания сеанса, потребуется снова открыть мастерскую и подтвердить аккаунт.

После первой загрузки фотографий технические идентификаторы путешествия и главы фиксируются независимо от отображаемых названий. Название можно исправлять без разрыва ссылок на уже загруженные R2-файлы. Для черновиков, созданных старой версией мастерской, сообщение «фотографии привязаны к старым идентификаторам» означает, что название менялось между загрузками: перезагрузите фотографии только в перечисленных сообщением главах и повторите отправку.

### Как подготовить Google Фото

1. Создайте **отдельный альбом для каждой главы**, например «Грузия — Тбилиси».
2. Добавьте туда только те фотографии, которые можно использовать для этой главы.
3. В Google Фото нажмите «Поделиться» → «Создать ссылку».
4. Вставьте ссылку в поле главы и проверьте её в приватной вкладке браузера: альбом должен открываться без входа в ваш аккаунт.

Не вставляйте ссылку на всю медиатеку. Общая ссылка на альбом сообщает редактору точный набор кадров, но не даёт сайту постоянный программный доступ к вашему аккаунту Google.

После добавления JSON в каталог `requests/` GitHub Actions автоматически проверит заявку, создаст скрытый черновик, зарегистрирует его и закоммитит сгенерированные файлы. Повторный запуск безопасен: уже созданные поездки пропускаются.

Локально тот же процесс запускается одной командой:

```bash
npm run trip:process
```

## Резервный способ: команда

Из корня проекта выполните:

```bash
npm run trip:new -- \
  --id georgia-2027 \
  --title "Грузия 2027" \
  --subtitle "Тбилиси, Сванетия и море" \
  --period "Май 2027" \
  --description "Путешествие по городам и горам Грузии" \
  --cover "https://example.com/cover.jpg"
```

`--id` — постоянный технический идентификатор. Используйте только строчные латинские буквы, цифры и дефисы; после публикации его лучше не менять. `--cover` необязателен и может указывать на любой доступный по HTTPS файл — Cloudinary не требуется.

Команда автоматически:

- добавит карточку в `data/trips.json`, поэтому поездка появится на главной;
- создаст публичную страницу `trips/georgia-2027/index.html`;
- создаст `data/georgia-2027/trip.json` с тремя начальными представлениями: «Главы», «По темам» и «По местам».

## 2. Добавить материалы

Откройте `data/georgia-2027/trip.json` и добавляйте элементы в нужные `views[].items`. Путешествие не обязано состоять из дней: главой может быть место, тема, человек или отдельная история.

```json
{
  "id": "tbilisi",
  "title": "Тбилиси",
  "description": "Дворы, серные бани и вечерний город.",
  "href": "chapter-tbilisi.html"
}
```

Один материал можно добавить ссылкой в несколько представлений, например одновременно в «Главы», «Города» и «Архитектура».

## 3. Отобрать фотографии на телефоне

1. Откройте на сайте `/photo-import.html`.
2. Нажмите **«Выбрать фотографии»** и выберите снимки из медиатеки или приложения «Файлы».
3. Дождитесь локальной проверки резкости, экспозиции и дублей.
4. Просмотрите предварительный выбор и скачайте JSON.

Страница не является облачным хранилищем: оригиналы никуда не отправляются. После отбора выбранные файлы нужно положить в доступное хранилище или каталог сайта, а их URL добавить в материалы. Для мобильной загрузки без Cloudinary практичный следующий этап — подключить хранилище с системным выбором файлов (например, репозиторий через форму загрузки или S3-совместимое хранилище); текущая версия намеренно выполняет только безопасный локальный отбор.

## 4. Проверить и опубликовать

```bash
npm test
python3 -m http.server 8000
```

Откройте `http://localhost:8000/trips/georgia-2027/`, проверьте все представления, затем закоммитьте изменения. Пока `status` равен `active`, поездка видна на главной; значение `hidden` скрывает её.

## Как избегать конфликтов Pull Request

- Создавайте новую короткоживущую ветку от актуальной `main` для каждой отдельной задачи.
- Перед началом следующего изменения обновляйте ветку из `main`; не продолжайте неделями один большой Pull Request.
- Не редактируйте одновременно в разных ветках генерируемые `data/*/trip.json` и `trips/*` для одного путешествия.
- Workflow проверяет feature-ветки, но коммитит сгенерированные черновики только после попадания заявки в основную ветку. Поэтому бот больше не дописывает коммиты прямо в открытый Pull Request.
